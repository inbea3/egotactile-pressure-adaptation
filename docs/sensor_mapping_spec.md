## 1. Three distinct sensor representations

1. Original source pressure vector: 256 values.
2. OXT spatial layout: 162 channels in a 17×19 nonzero grid.
3. Unique physical source sensors: 137 indices.

The OXT `right_tactile_raw_index_pressure` field uses the same **1-based source index convention** as the official mapping note. Subtract one only when indexing a Python array such as `right_tactile_raw_pressure_256`.

## 2. Functional areas and six analysis regions

The official note defines 11 functional areas:
- thumb_tip, index_tip, middle_tip, ring_tip, little_tip;
- palm;
- thumb_bend, index_bend, middle_bend, ring_bend, little_bend.

For the primary structural target, group them into six hand regions:

| Analysis region | Official functional areas | Unique physical sensors | OXT layout channels |
|---|---|---:|---:|
| Thumb | thumb_tip + thumb_bend | 13 | 18 |
| Index | index_tip + index_bend | 13 | 18 |
| Middle | middle_tip + middle_bend | 13 | 18 |
| Ring | ring_tip + ring_bend | 13 | 18 |
| Little | little_tip + little_bend | 13 | 18 |
| Palm | palm | 72 | 72 |
| **Total** | 11 areas | **137** | **162** |

## 3. Bend sensor reconstruction

There are 132 physical sensors represented by one layout channel each, plus five physical bend sensors represented by six virtual layout cells each.

The official note states that each bend virtual cell stores one sixth of the source bend sensor value. Therefore:
- do not retain only one of the six cells;
- do not count the six cells as six independent physical sensors;
- sum all six virtual cells sharing the same raw source index to reconstruct that physical bend sensor's value;
- assign the reconstructed bend sensor to its corresponding finger region.

The five repeated source raw indices (1-based) are:
- 47: thumb bend;
- 44: index bend;
- 41: middle bend;
- 38: ring bend;
- 35: little bend.

Their layout-channel groups are generated by `scripts/build_sensor_mapping.py`, not manually hard-coded in downstream model code.

## 4. Primary regional load definition

For each time sample:
1. reconstruct 137 physical sensor values from the 162 layout channels by grouping on source raw index and summing virtual bend cells;
2. assign each physical sensor to one of six regions;
3. calculate regional load as the sum of physical sensor values in that region;
4. calculate total hand load as the sum of the six regional loads;
5. calculate regional load share only when total hand load exceeds the frozen valid-load threshold.

This prevents virtual bend-cell duplication from inflating a region's sensor count or total load.

## 5. Sample-level crosswalk validation — passed

The mapping crosswalk workflow validated Apple, SprayBottle, and TennisBall at the pinned dataset revision. All three objects passed:
- `right_tactile_raw_index_pressure` exactly matches the official 1-based source-index sequence;
- raw-index mapping is constant across all frames;
- `right_tactile_grid_xy_pressure` exactly matches the official grid coordinates when interpreted in stored `[x, y]` order (the note describes each point as `y, x`);
- grid mapping is constant across all frames;
- all five six-cell bend groups have identical per-cell pressure values across frames;
- pressure transform metadata states that the five bend source channels are expanded to six virtual cells and divided by six, with pressure unit N.
